# ADR-008：文档生成

| 项目 | 内容 |

## 2. 上下文（Context）

需要从不可变 Snapshot 一键生成"现状调研报告"与"需求清单"的 DOCX/PDF，
要求中文分页正确、对象编号与来源可回链、同输入重复生成内容一致、敏感对象按权限脱敏，
且**图文不脱节**（风险 R6）。文档生成是异步、耗时、可能涉及不可信文件的环节，
需要与主服务隔离并具备降级能力。

上游 §2.2 裁定"文档与 3D 只读 Snapshot"，§7.3 定义五层模板与生成链路
（预检 → Document IR → DOCX → 隔离 Worker 转 PDF → 哈希 → 对象存储 → 登记 artifact）。

## 3. 决策（Decision）

1. 引入 **Document IR**（`packages/document-ir`）：与格式无关的文档内容模型，
   章节查询、对象引用、图表快照、敏感字段策略在此表达。
2. DOCX 生成使用 **docx 库**（Node）。
3. PDF 由**隔离的 LibreOffice Worker** 转换（受限容器，限制 CPU/内存/超时）。
4. 生成链路固定为：预检（未确认 / 敏感 / 权限 / 图表 / 模板兼容）→ Document IR →
   DOCX → LibreOffice → PDF → `sha256` → 对象存储 → 登记 `document_artifact`。
5. 文档**固定关联 Snapshot**，模板冻结，产物不可变；对象使用稳定编号（如 `REQ-023`），
   每条需求可回到来源对象编号与证据。
6. 用户只做内容级调整（纳入/排除、措辞、顺序），不调字体与页边距。
7. 未选快照或模板时拒绝创建 `document_job`；失败需可定位到章节。

## 4. 理由（Rationale）

- Document IR 解耦内容与格式，使网页预览、DOCX、PDF 从同一来源生成，保证一致（P1）。
- docx 库类型友好、可编程生成，符合 TS 贯通。
- LibreOffice 转 PDF 覆盖中文与分页，隔离运行以限制不可信文件风险。
- 与 Snapshot 绑定从结构上防止"文档可手改脱离模型"（R6）。

## 5. 后果（Consequences）

### 正面

- 同模板 + 同快照重复生成结构与对象内容一致（可哈希校验）。
- 网页预览与导出文档同源，图文一致性可抽查。
- 渲染器可替换，IR 不受实现影响。

### 负面

- 维护 IR 与两套渲染路径，工作量大。
- LibreOffice Worker 需容器与资源限制，私有部署体积与运维成本上升。
- 中文字体、分页细节需要反复调试。

### 风险

- 中文分页/字体不正确。对策：M0-07 用中文不可变样本做 DOCX/PDF 冒烟与两次哈希对比。
- 文档脱离模型被手改。对策：网页预览内容选择 + 快照引用 + 回链来源对象。
- 隔离 Worker 逃逸或资源耗尽。对策：受限容器 + 超时/内存/页数限制 + 不执行宏脚本外链。

## 6. 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 直接在 API 进程内转 PDF | 无隔离，不可信文档风险高，阻塞主服务 |
| 纯模板字符串拼接生成 DOCX | 无 IR 抽象，格式与内容耦合，难维护 |
| 在线 SaaS 文档渲染 | 私有部署不友好，数据外发不可控 |
| 手写 PDF 生成库（不支持 DOCX） | 需求要求 DOCX/PDF 双格式 |
| 让用户用富文本编辑器排版 | 首版不做通用富文本编辑器（§1.2） |

## 7. 验证方式

1. 文档冒烟（M0-07）：从不可变样本生成带对象编号的 DOCX/PDF，检查中文字体与分页，
   两次生成哈希一致。
2. 一致性抽查（M8-06）：文档对象编号、来源、状态、图形与 Snapshot 一致。
3. 幂等测试（M8-03）：同模板 + 同快照重复生成结构一致；失败章节可定位。
4. 预检测试：未确认对象、敏感对象、模板不兼容均被拦截或脱敏。
5. 隔离测试：LibreOffice Worker 在 CPU/内存/超时限制下运行，超限被终止且不影响主服务。

## 8. 重新评估触发条件

- 中文分页或字体无法用 docx + LibreOffice 满足需求。
- 复杂文档 / 专用 AI 库不可替代（联动 §2.3 Python 否决项的重新评估触发）。
- 文档生成性能或私有部署体积不可接受。
- 需要真正的富文本在线编辑（超出首版范围）。
