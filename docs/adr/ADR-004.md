## 2. 上下文（Context）

目标是让普通客户在首次接触时**理解流程**，而不是追求视觉炫技。3D 用于导览演示，
承担"可复述"的理解任务。约束：

- 3D **不承载独占信息**，与 2D 语义等价。
- 目标办公机性能未知，WebGL 可能不可用或性能不足。
- 资产制作与物理仿真会显著拖慢进度（风险 R1"3D 过度设计"）。

上游 §2.2 与开发方案 §7.1 裁定 3D 只消费投影结果，坐标/相机/动画属展示布局，
不回写语义。需要一个确定性的投影层保证 3D 与 2D 一致且可降级。

## 3. 决策（Decision）

1. 采用 **Three.js + React Three Fiber + Drei（R3F）** 作为渲染层。
2. 定义 **SceneProjection** 中间模型：由 Snapshot 经**确定性投影器**生成，
   描述低多边形角色、区域、站点、路径与故事镜头；3D 渲染器只消费 SceneProjection。
3. 3D 采用**低多边形导览**：不使用写实个人形象，不做物理仿真与精确编辑。
4. **WebGL 不可用或性能不足时自动/手动降级为 2D 故事视图**，保留同一故事步骤、
   旁白、对象卡与评论，内容不丢失。
5. 同一快照的投影必须确定：相同输入生成相同 SceneProjection。
6. 3D 的所有交互（镜头、拾取、步骤播放）属展示状态，**不回写语义**。

## 4. 理由（Rationale）

- R3F 与 React 状态衔接顺畅，支持 glTF 与降级路径，生态成熟。
- SceneProjection 作为中间层使 3D 与 2D 共享同一事实来源，语义等价可验证。
- 低多边形 + 导览而非编辑，控制资产成本与性能风险（P6 闭环优先于广度）。

## 5. 后果（Consequences）

### 正面

- 3D/2D 语义等价可自动化校验（同一快照投影一致、对象卡可回链）。
- 降级路径清晰，弱设备与无 WebGL 环境仍可完成演示。
- 渲染器可替换，领域模型不受影响。

### 负面

- 需要维护投影器与 3D 渲染器两套代码，资产规范也是新增维护面。
- 低多边形风格对"写实预期"有落差，需要产品与客户预期管理。
- 投影确定性与性能探测需要额外测试。

### 风险

- 资产与镜头打磨吞噬工期（R1）。对策：M0 先证明降级机制，视觉细节推迟到 M7。
- 目标设备 WebGL 支持不确定。对策：M0-04 完成降级证明，并纳入目标设备表。

## 6. 被否决的替代方案

| 方案 | 否决原因 |
| --- | --- |
| 3D 精确编辑 / 数字人 / 物理仿真 | 属首版不做范围，成本高、收益低（§1.2） |
| 超写实资产 / 多人 3D 共游 | 首版不做，性能与内容成本不可控 |
| 2D-only（不做 3D） | 放弃客户理解增益；产品已要求 3D 导览 |
| 第三方低代码 3D 平台 | 私有部署与深度定制受限，绑定风险高 |
| 直接渲染 2D 模型（无投影层） | 无法保证 3D/2D 语义等价与降级一致 |

## 7. 验证方式

1. 投影确定性测试（M7-01）：同一 Snapshot 两次投影，SceneProjection 深度相等。
2. 语义等价测试（M7-05）：WebGL 不可用时进入 2D 故事视图，步骤、旁白、对象卡、
   评论仍可用，对象 ID 与专业视图一致。
3. 降级演练：在禁用 WebGL 的浏览器上下文中，页面自动进入 2D 且无功能缺失。
4. 性能探测：M0-04 / M7-05 记录 3D 载入时间与帧率，超阈值触发降级。
5. 可访问性：文本等价列表、键盘控制、减少动画选项可通过清单检查（M7-06）。

## 8. 重新评估触发条件

- 目标设备普遍无法承载 3D，降级成为常态路径。
- 客户理解测试（M7-07）显示 3D 未带来可测的理解增益。
- SceneProjection 无法表达业务需要的关键叙事结构。
- R3F 版本升级与 React 版本出现不可调和冲突。
