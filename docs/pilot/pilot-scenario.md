# 试点场景说明书 · Odoo 通用贸易「报价到回款」

> 对应实施方案 §6.1（M0-01）与 §8.2 金样例。本文件是**基准项目说明书**，
> 也是 M0 四个 Spike 的**共同输入**。

## 1. 场景边界

- **行业**：通用贸易（批发/分销），基于真实 Odoo 实施现场。
- **项目**：`PRJ-TRADE-001`，当前 `projectRevision = 1`。
- **流程范围**：从「客户询价」到「回款登记完成」的端到端主链，即 **线索/询价 → 编制报价 → 折扣判断 → 审批 → 信用检查 → 销售订单 → 发货 → 开票 → 回款**。
- **不覆盖**：售后维修、退换货、多币种结算、税务申报（后续里程碑处理）。
- **系统现状**：核心交易在 `Odoo`（`SYS-001`）中完成；销售与客户沟通仍大量依赖「微信 / 在线表格」（`SYS-002`），存在数据割裂。

## 2. 参与岗位

| code       | 岗位     | 主要职责                                       |
| ---------- | -------- | ---------------------------------------------- |
| `ROLE-001` | 销售员   | 登记询价、编制报价、创建销售订单               |
| `ROLE-002` | 销售经理 | 折扣审批、销售过程负责（多数活动 accountable） |
| `ROLE-003` | 财务     | 信用检查、开票、回款登记、信用/逾期特批        |
| `ROLE-004` | 仓库     | 发货                                           |
| `ROLE-005` | 采购     | 缺货时配合采购（被咨询）                       |
| `ROLE-006` | 客户     | 外部参与方（被通知）                           |

## 3. 主流程

1. `START-001` 询价受理 → `ACT-001` 登记线索/询价（销售员）
2. `ACT-002` 编制报价（销售员，产出 `DO-001` 报价单）
3. `DEC-001` 折扣是否超 10%
   - 是 → `ACT-003` 折扣审批（销售经理）
   - 否 → 直接进入 `ACT-004` 信用检查
4. `ACT-004` 信用检查（财务，使用 Odoo）
5. `DEC-002` 客户是否逾期
   - 否 → `ACT-005` 创建销售订单（产出 `DO-002`）
   - 是 → `ACT-009` 信用/逾期特批（财务）→ 继续下单
6. `ACT-006` 仓库发货（产出 `DO-004` 发货单）
7. `ACT-007` 开票（产出 `DO-003` 发票）
8. `ACT-008` 回款登记（产出 `DO-005` 银行回款记录）→ `END-001` 订单闭环

## 4. 分支与异常清单

| 类型     | code      | 条件/触发               | 去向                                |
| -------- | --------- | ----------------------- | ----------------------------------- |
| 决策分支 | `DEC-001` | 折扣 > 10%              | 提交销售经理审批（`ACT-003`）       |
| 决策分支 | `DEC-001` | 折扣 ≤ 10%              | 无需审批，进入信用检查（`ACT-004`） |
| 决策分支 | `DEC-002` | 未逾期                  | 允许下单（`ACT-005`）               |
| 决策分支 | `DEC-002` | 已逾期                  | 转财务特批（`ACT-009`）             |
| 异常     | `EXC-001` | 折扣审批超时（SLA 24h） | 升级销售经理重审（`ACT-003`）       |
| 异常     | `EXC-002` | 信用不足/额度不足       | 转信用/逾期特批（`ACT-009`）        |

> 所有决策出口均带**条件标签**；所有异常均有**明确去向**；主链可到达 `END-001`。

## 5. 证据来源清单

证据为**独立实体**（与 `modelObject` 分表，实施方案 §4.1「调研与证据」；分级脱敏见 §7.4「导出」），拥有独立数据分级；
证据到对象的关联由 `evidenceLink` 承载（原 `supported_by` 语义迁移至此）。

| code     | type                | locator（定位）                  | provider | capturedAt | classification | 关联对象（evidenceLink）                                                                |
| -------- | ------------------- | -------------------------------- | -------- | ---------- | -------------- | --------------------------------------------------------------------------------------- |
| `EV-001` | `interview_segment` | 销售员访谈录音 00:12:30-00:13:10 | 销售员   | 2026-03-12 | `internal`     | `ACT-001`、`DEC-001`、`ACT-003`、`PROB-001`、`REQ-001`                                  |
| `EV-002` | `form_sample`       | 现用报价单模板.xlsx / Sheet1     | 销售员   | 2026-03-15 | `internal`     | `ACT-002`、`ACT-005`、`ACT-006`、`REQ-001`                                              |
| `EV-003` | `interview_segment` | 财务访谈录音 00:05:10-00:06:20   | 财务     | 2026-03-18 | `sensitive`    | `ACT-004`、`DEC-002`、`ACT-009`、`ACT-007`、`ACT-008`、`PROB-002`、`REQ-002`、`REQ-003` |

> `EV-003` 标记为 `sensitive`（涉及信用与坏账），用于让 M7（3D/故事线读快照）与
> M8（文档预检与脱敏）有可测的真实分级数据。
> 每条 `evidenceLink` 均带最小引用 `excerpt`（不得整段复制材料）与 `purpose`。
> 关键事实对象（`activity` / `decision` / `problem` / `requirement`）均至少有一条 `evidenceLink`。
