# 里程碑复核制度

| 项目 | 内容 |
| --- | --- |
| 文档性质 | 里程碑只读复核制度说明 |
| 版本 | v1.0 |
| 编制日期 | 2026-10-04 |
| 上游依据 | 《需求调研工作台-具体实施方案》§8.4、§9.1、§9.2、§10；《需求调研工作台开发方案》§8.7、附录 D、附录 E |

本目录定义里程碑验收与只读复核的执行方式，确保"里程碑阻断项全部关闭，才允许进入下一
里程碑"。复核的目标不是挑错，而是用**可复现的证据**判断里程碑是否真正达标。

---

## 1. 角色与边界

| 角色 | 职责 | 边界 |
| --- | --- | --- |
| 开发者 | 本地实现、测试并提交；提供 commit SHA 与启动说明 | 不得在复核前自评"通过" |
| 总指挥 | 只读拉取，核对范围 / 依赖 / 架构边界 / 迁移 / 测试 / 验收证据；输出四类清单 | **未经明确授权不直接修改业务代码** |

复核是**只读**行为。复核者只在清单中标注"文件/接口/测试定位"，不代替开发者改代码；
修复由开发者推新 commit 完成（开发方案 §8.7）。

---

## 2. 复核触发时机

| 时机 | 说明 | 输入 |
| --- | --- | --- |
| 每个里程碑结束 | M0~M8 每个里程碑完成后必须复核一次 | 提交包 + 验收证据（第 4 节） |
| 阻断项修复后复验 | 开发者针对"必须改"推送新 commit 后 | 新 commit SHA + 变更说明 |
| 变更单裁定后 | 新增对象/页面/接口/依赖获批并落地后 | 变更单 + 影响范围 |
| 按需抽查 | 出现疑似越过架构红线时 | 具体嫌疑点定位 |

> 未触发上述时机的中间提交不进入正式复核；但**不得用未验收的后续界面掩盖底层缺陷**
> （实施方案 §6 执行方式）。

---

## 3. 四类输出清单

复核结论只允许归入以下四类，每条必须标注**文件 / 接口 / 测试定位**：

| 类别 | 含义 | 处置 |
| --- | --- | --- |
| 必须改 | 阻断里程碑或违反红线的问题 | 必须关闭后才可进入下一里程碑 |
| 建议改 | 不阻断但影响质量、可维护性或后续成本 | 记录，排期修复，不阻断 |
| 历史遗留 | 既有问题，非本轮引入，本轮不要求修复 | 登记影响与归属 |
| 待确认 | 需产品负责人或总指挥裁定的开放项 | 指定负责人与最晚确认时点 |

**禁止**输出第五类，或把"必须改"降级为"建议改"以放行里程碑。

---

## 4. 提交包与验收证据

每个里程碑提交包须包含（实施方案 §9.1）：

| 交付项 | 内容 |
| --- | --- |
| 代码 | commit SHA / tag；无未提交文件 |
| 启动 | README + 一条本地启动命令 |
| 迁移 | Schema 变化、升级测试、恢复说明 |
| 契约 | OpenAPI、Schema、示例请求/响应 |
| 测试 | 自动化结果与手工任务清单 |
| 演示 | 固定 seed、操作路径、截图/短录屏 |
| 决策 | 新增/更新 ADR 与待确认项 |
| 已知问题 | 影响、临时规避、后续里程碑 |

验收证据统一使用 [milestone-evidence-template.md](./milestone-evidence-template.md)；
复核执行统一使用 [readonly-review-checklist.md](./readonly-review-checklist.md)。

---

## 5. "从干净环境复核"的具体含义

"干净环境"必须是**未复用开发者工作副本**的环境，且满足：

1. **全新克隆**：从仓库地址重新克隆到空目录，切到被复核的 commit SHA/tag；不复用
   开发者本地未提交文件或缓存。
2. **版本对齐**：按 `.nvmrc` 切换到指定 Node 版本（当前基线 Node 22），
   用仓库记录的包管理器版本安装；`pnpm install --frozen-lockfile` 必须无 lockfile 漂移。
3. **空库启动**：数据库从空库开始，执行 migration 与 seed 重建演示样本；空库迁移与
   上一版本升级路径都要能被验证（实施方案 §4.5）。
4. **一条命令启动**：按 README 的单一启动命令拉起，无隐藏手工步骤。
5. **容器栈可复现**（M1 起）：容器编排带 healthcheck，干净环境可复现。
6. **无秘密 / 无本地绝对路径**：日志与仓库中不含秘密、临时文件或本地绝对路径。

在本机无 Docker 的情况下，依赖容器栈的验收点必须在其具备容器的环境执行，
**不得凭非容器环境的运行结果判定通过**（见 ADR-010 的置信度限制）。

## 6. 硬规则

> **里程碑阻断项全部关闭，才允许进入下一里程碑。**

- 阻断项 = 四类清单中的全部"必须改"条目，以及提交包/证据中的缺项（如未验证项未列明）。
- 复验在**新 commit** 上从干净环境重新执行，条目"关闭"或"继续保留"，不允许口头关闭。
- 若某里程碑阻断项未关闭，宁可顺延，也不进入下一里程碑（实施方案 §1.6）。
- 与上游文档冲突时，以上游为准并暂停实现，提交变更单裁定（实施方案 §0.1）。
